🔧 WHY THIS WORKS:

The core issue: The Workload Identity Pool was corrupted from previous
failed setup attempts. It cached bad validation state internally.

The solution: Delete everything and create a fresh pool. GCP doesn't
accept the same OIDC provider creation command once a pool has been
in a bad state. Fresh creation always works.

The script:
1. Deletes the corrupted pool (cascades to delete provider)
2. Waits 10 seconds for GCP to fully propagate
3. Creates a brand new pool (clean state)
4. Creates provider with correct attribute-mapping
5. Completes all remaining setup
6. Shows the values needed

🆘 IF SOMETHING GOES WRONG:

Problem: Script fails at pool deletion
  → Try again, sometimes GCP needs a moment
  → Check you're using WSL gcloud (not Windows gcloud)

Problem: Script completes but provider creation still fails
  → The pool might still be corrupted
  → Delete manually: gcloud iam workload-identity-pools delete github-pool...
  → Wait 20 seconds, try script again

Problem: GitHub workflow fails to authenticate
  → Check all 3 GitHub Variables are set exactly as shown
  → Re-copy the values from script output
  → The WIF provider value is especially important (long string)

Problem: Anything else
  → Read: .github/workflows/COMPLETE_SETUP_GUIDE.md
  → Check: .github/workflows/FIX_INVALID_ARGUMENT_ERROR.md
